# Testing frozen-layer caching for TCO on the RTX 3080

**SOL handoff, 20 November 2026. Planning only until the user resumes the goal.** Determine whether VGGT can adapt to a scene with lower latency and peak GPU memory by running its early multi-view layers once and reusing their outputs. Keep RunPod compute at **USD 0**. Use one local RTX 3080 job at a time. Complete the goal with reproducible positive, negative or inconclusive evidence on the three development scenes.

## What SOL should establish

Compare cached TCO with ordinary full-decoder TCO at **5, 10 and 40 updates**. The target, relative to a freshly timed 40-step implementation on the same machine, is **at least 2× faster, at least 20% lower peak allocated GPU memory, and at most 1% relative degradation in each of surface accuracy error and completeness error**. A shorter full-decoder run at the same or lower latency is also a competitor. Keep the two findings separate: restricting which layers learn can change reconstruction quality, while caching an already frozen prefix should reproduce the corresponding uncached suffix model.

The previous Heads feasibility run took 227.90 seconds on five 392 × 518 images and peaked at 8.63 GiB allocated and 10.57 GiB reserved. It skipped surface evaluation. Even the zero-step run peaked at 8.10 GiB allocated. If the new 40-step baseline matches the historical one, the resource targets are roughly 114 seconds and 6.90 GiB. The initial forward alone could defeat the memory target. Use current matched measurements for every verdict. ## Implement the cache

VGGT's aggregator has 24 stages in the pinned configuration. One stage comprises a frame attention block followed by a global attention block. The active depth head reads concatenated frame/global outputs at zero-based indices **4, 11, 17 and 23**. The camera head reads the last output. Inspect the actual configuration and assert these indices at startup. The existing offload wrapper removes the unused point head and sends the patch encoder to CPU after its output has been cached. Use that wrapper's behavior in every positive-step baseline. [Pinned TCO loop](https://github.com/cvlab-stonybrook/TCO/blob/65387333877723cf99086f7f29089379dd50c59a/tco_vggt_lora.py) · [Pinned depth head](https://github.com/cvlab-stonybrook/TCO/blob/65387333877723cf99086f7f29089379dd50c59a/base_models/vggt/vggt/heads/dpt_head.py)

| Trainable suffix | Frozen paired stages | Boundary tensor to cache | Frozen depth-head outputs to retain |
|---|---|---|---|
| Last 12 stages | 0–11 | Raw tokens after global block 11 | 4, 11 |
| Last 6 stages | 0–17 | Raw tokens after global block 17 | 4, 11, 17 |

1. First implement a full-decoder baseline which constructs only the four concatenations used by the heads. Preserve their original indices and the camera head's final lookup. All intervening blocks still run. Test the zero-step and one-step outputs against the existing offloaded full-decoder implementation.
2. Add the two uncached suffix variants. Restrict LoRA installation to the corresponding stages in **both** attention stacks. The upstream helper enables all installed LoRA gradients. Assert that the optimizer contains exactly the intended tensors and the frozen weights stay unchanged. Initialize shared suffix adapters from identical tensors keyed by fully qualified name. Changing the number of wrappers can otherwise change random initializations and the subsequent render samples.
3. Cache the **raw post-global hidden state**, including special tokens, in its original dtype and layout. Preserve positional indices, view order, patch offset, shape and the frozen depth-head outputs. Continue the live suffix at the next stage and retain gradients through all its live outputs. Use detached tensors compatible with autograd in the suffix. Preserve upstream suffix checkpointing and evaluation mode. Scope cache lifetime to one scene and run. Count cache bytes by device, builds, hits and executed prefix stages. Discard the cache if inputs, parameters, preprocessing, precision or mode change.
4. Inspect autocast separately for the original prediction, gradient-bearing update and final inference. Reuse the original pass to construct a cache only if the boundary outputs match the required context. If the final readout needs a different precision, build its own prefix output or recompute it and charge that work. Account for early head outputs as well as the suffix input. All candidates retain the full image resolution, view set, priors, render loss and final reconstruction.
5. Implement an explicit placement policy before running the benchmark. Keep the original model on CPU initially if full GPU residency would set an unavoidable peak. Stage the patch encoder, frozen prefix and live suffix as needed, and evict unused modules before the next phase. Charge device transfers and measure host memory. Separate the benefit of placement from caching in the control rows. In the uncached suffix control use the same placement and recompute the frozen prefix in each update. Document any unavoidable difference in residency duration.

## Correctness before timing

Use a small deterministic fixture first, followed by one full-resolution Heads check. Compare the ordinary and four-output full-decoder paths, then compare cached and uncached versions of **each identical suffix**. Use the same adapter tensors, optimizer state and render view groups. Record or replay the actual random draws and verify the legacy sampler's sequence. Compare boundary tensors and depth features, depth/confidence and camera outputs, individual loss terms, per-adapter gradients **before clipping**, factors after one Adam step, and final predicted geometry after a short run. Check counts and frozen hashes. A changed input order must invalidate the cache.

Expect exact equality for tensors generated by the same deterministic forward operations in the same precision. TCO has shown same-seed backward variation. Establish the uncached-versus-itself repeat envelope using a separate technical fixture and freeze a numeric tolerance by tensor/metric before inspecting the cached comparison. Record both relative norm and maximum absolute differences. Investigate systematic disagreement, incorrect autocast, stale cache or different RNG before benchmarking. If equivalence cannot be established, report the affected variant as numerically unresolved. Distinguish this from the expected quality difference between full and suffix-only adaptation. - **Latency.** Synchronize CUDA at the start and end. For every primary run start with RGB, priors and the loaded base checkpoint on CPU, before any model or scene tensor is placed on the GPU. Charge all subsequent placement, first prediction, cache construction, updates, transfers and final usable reconstruction. Separately report cold start from checkpoint loading through final prediction, and the inference/adaptation interval used by the historical runner. Use the same untimed runtime/extension warm-up with unrelated inputs across arms and release its tensors before measurement. Isolate instrumentation runs with expensive per-tensor synchronization, profiler traces or JSON writes. Use the same lightweight instrumentation for all primary timings.
- **Memory.** Keep one uninterrupted GPU high-water measurement across device placement, original pass, cache build, adaptation and final inference. Log allocated and reserved peaks, plus per-phase estimates on separate profiling runs or with a running maximum. Also report process peak from checkpoint load, host RAM, cache bytes, and device-wide usage/free memory before and during execution where available. A per-phase reset cannot discard an earlier peak. Monitor WSL/shared-memory pressure. Mark OOMs with their phase and include attempted settings. Keep a complete record of retries.
- **Geometry.** Use one fixed reference mask and preprocessing for all variants. Retain camera, intrinsics and depth outputs for a common readout at fixed precision, including step zero. Score corresponding predictions with the existing Umeyama similarity alignment, rigid ICP and nearest-neighbor evaluator. Report mean accuracy error (predicted surface to reference) and mean completeness error (reference to predicted surface) separately, in mm. Record normal consistency as a secondary measure. Compare with the ordinary pipeline export to expose readout differences. Keep evaluation outside model timing. ## Decide what the results support

Use the four-output full 40-step arm as the primary reference after its correctness check. Report the original offloaded 40-step reference alongside it. For each arm take the median over the three paired runs within each scene for each metric. Compute candidate/reference ratios per scene, then their unweighted arithmetic mean across scenes. Display individual runs, scene medians, worst-scene changes and the observed spread. Define speedup as the reciprocal of the aggregated latency ratio.

1. **Resource and quality gates.** Advance a candidate only if the mean latency ratio is at most 0.50, peak allocated memory ratio at most 0.80, and both surface-error ratios at most 1.01. Report whether full TCO and the candidate also improve on zero-step VGGT. If variability at a decision boundary could reverse the verdict, label the comparison inconclusive or use a prospectively registered paired repeat; do not cherry-pick fast launches. A reduced steady-state peak with unchanged full-scene peak is a phase-specific result.
2. **Equal-time challenge.** Among the full-decoder 5-, 10- and 40-step controls in either implementation whose aggregated latency is at most the candidate's, identify the one with the lowest average of its two normalized surface errors (tie-break by lower time, then lower memory). Normalize each error by the same full-40 reference. Require the candidate to improve this score while keeping each component within 1% of the time-matched control. Show the full accuracy/time/memory frontier, including zero-step VGGT. If no adapted control fits the observed time, report that fact and compare with zero. To claim an improvement over fewer steps at matched time in that situation, add the largest shorter full-TCO budget fitting the candidate, chosen using **timing only** before inspecting its quality. If only zero fits, limit the claim accordingly.
3. **Attribution and stopping.** Use cached versus identical uncached suffix results to quantify time and memory saved by reuse. Use suffix versus all-adapter controls to quantify the quality cost of freezing. If multiple candidates pass, nominate the fastest, breaking ties by lower memory then the shorter trainable suffix. A negative result ends this goal and should say which phase or quality metric defeated the approach. These three rooms are exposed development data. Independent scenes and broader publication claims require a subsequent study.
