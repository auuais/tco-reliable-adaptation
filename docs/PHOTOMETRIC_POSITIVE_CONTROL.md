# Can the RGB rule recover a known depth error with reference cameras?

The first dense RGB pilot accepted a change on 0.88% of valid pixels, and about 23% of the modified pixels improved under the fixed registered reference alignment. Run a positive control to distinguish the photometric signal from errors in frozen cameras, visibility depth and starting shape. This is an evaluation experiment with privileged reference geometry. It cannot authorize spending or serve as an inference method.

Recover each registered camera by fitting a pinhole projection to up to 512 deterministic valid pixel/world-point pairs. Verify projection of **all** valid points, including the complement of the fit pixels, to a maximum error of 0.02 pixels. Derive the true axial depth in its native camera coordinates. For each target, keep the four source depths and camera poses at these reference values. Cross three target starting depths, given by the reference axial depth times exp(−0.08), 1 or exp(+0.08). Only valid target reference pixels enter the counts. Invalid source depth cannot support a warp. Use the sealed five candidate factors, appearance costs, visibility thresholds, baseline-ranked split and three selection rules without retuning. Also report the nearest source alone with the same candidate footprints for a measure of pairwise signal availability.

For every setting report all valid pixels, pixels eligible for the rule, non-identity changes, exact target-depth recovery, and moves that reduce absolute log-depth error. Report false edits on initially correct depth. Evaluate the nine unique RGB batches, balancing the twelve original conditions, with per-scene results for the two injected signs. A restored sign or correct candidate under this idealized test does not demonstrate the same precision on unknown natural model errors. This local experiment adds no cloud compute.
