# The camera frame changes agreement with the RGB images

The original 7-Scenes KinectFusion poses describe the depth sensor. We verified that all 15 development pose files are byte-identical to the public originals and that the reconstruction loader inverted those poses directly. The depth preprocessing pipeline separately maps depth measurements into the RGB camera. Composing the depth-to-RGB transform with each world-to-depth pose reduced the median RGB-track reprojection error on all three scenes under the released intrinsics. This establishes a frame sensitivity in our benchmark. The dataset authors describe the original RGB and depth camera pair as uncalibrated. The preprocessing transform is an approximate Kinect calibration. [ICCV paper](https://openaccess.thecvf.com/content/ICCV2021/papers/Brachmann_On_the_Limits_of_Pseudo_Ground_Truth_in_Visual_Camera_ICCV_2021_paper.pdf) · [Microsoft dataset description](https://www.microsoft.com/en-us/research/project/rgb-d-dataset-7-scenes/) · [TCO loader](https://github.com/cvlab-stonybrook/TCO/blob/65387333877723cf99086f7f29089379dd50c59a/datasets/sevenscenes.py)

| Camera convention | Heads (px) | Chess (px) | Fire (px) |
|---|---:|---:|---:|
| Released poses and intrinsics | 10.80 | 7.46 | 8.08 |
| Same intrinsics, compose depth-to-RGB | 8.10 | 6.78 | 6.57 |
| Same intrinsics, inverse-direction control | 12.50 | 8.64 | 11.94 |
| Compose depth-to-RGB, use registration focal and per-axis image resize | 6.51 | 3.65 | 4.42 |
| Published RGB SfM poses and their estimated focal lengths | 5.78 | 2.42 | 2.81 |

Values are median Euclidean pixel errors for directed RGB matches with valid source depth and positive target depth. The full tables also count observations with nonpositive target depth. The frame correction alone lowered this error by about 25%, 9% and 19% respectively. Depth-independent median Sampson distance for the released intrinsics changed from 2.45 to 1.87 px on Heads, 3.12 to 2.99 px on Chess, and 1.75 to 1.84 px on Fire. The metrics therefore favor different conventions in some conditions. [All 27 conditions and directed-pair statistics](summary.json)

An additional sensitivity uses the authors' published RGB SfM poses for the same five frames per scene. We used their estimated focal length, assumed a centered principal point, and mapped the resized intrinsics with independent horizontal and vertical scales. For depth reprojection we matched the SfM median camera baseline to the registered-pose baseline. The scale factors were 0.989, 0.991 and 1.004. Median Sampson distances were 1.00, 0.49 and 0.39 px respectively. This measure is independent of the translation scale. The RGB SfM reconstruction uses imagery from the scene, so this is an alternative reference with shared visual information. [Published SfM poses and methodology](https://github.com/tsattler/visloc_pseudo_gt_limitations/tree/22b7c48a0e55b49d0214a8dbb022426f518e2795) · [Fifteen-frame results](alternative_rgb_sfm.json)

The experiments use the previously frozen RGB matches. No alternative pose or reference-depth label entered the camera selector. Same-view depth reprojection, axial-depth interpolation, nominal calibration and approximate image correspondences each have limits. The 7-Scenes calibration study measured aligned reconstruction error under its released reference, whereas this table measures pixel agreement. It would take fresh model comparisons under an explicitly chosen reference convention to establish an improvement in TCO reconstruction.

To reproduce the camera-frame audit, obtain the registered-depth preprocessing source identified by its hash in the manifest, the original sequence ZIPs, the prepared development frames, the v6 evidence and the frozen v8 RGB support. Run `scripts/audit_sensor_frame.py` with those paths. For the RGB reference, run `scripts/audit_public_rgb_poses.py fetch --subset SCRATCH` followed by its `score` action. The fetch retains only the specified 15 pose records locally.
