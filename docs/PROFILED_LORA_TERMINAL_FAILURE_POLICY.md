# Prospective terminal-failure recovery policy

Written November 18, 2026, before any observed numerical failure or development score in the scientific-v2 screen. This is a conditional recovery specification, **not an implemented or released execution path**. The active `screen02` batch and its registered code remain unchanged. See the [execution handoff](CALIBRATION_AWARE_LORA_HANDOFF.md) and [goal contract](CALIBRATION_AWARE_LORA_GOAL.md).

**When this policy can apply**

A failed run stops the current queue. Preserve its original public/raw attempt directories, error traceback, partial outputs, source/input/manifest hashes, initialization identity, logs and actual process/container exit status. Verify that its process stopped before any further GPU action. Do not overwrite, delete, conceal or reclassify an attempt merely to complete the inventory.

Only a genuine `FloatingPointError` may be classified as terminal numerical invalidity under this amendment. The exception name alone is insufficient: an engineering review must establish that the failure arose from the registered numerical method with valid inputs and unchanged computation. Audit the traceback, available state-integrity evidence, current source/runtime/checkpoint/input hashes, finite-input checks, registered precision and resource status without accessing development accuracy.

An OOM, timeout, interrupted process, corrupt input, changed source, filename/serialization error, missing evidence, or other exception remains an engineering/infrastructure or unclassified failure. An uncertain cause remains unclassified. Do not convert these failures to negative method evidence. Missing integrity evidence must be resolved before declaring numerical invalidity; record the limits of any audit.

Do not blindly repeat a deterministic numerical failure. A diagnostic may inspect the preserved failure and test its cause without study labels, but a repeated identical run is not a recovery strategy. A change to the model objective, arithmetic, masks or hyperparameters is a new method/protocol decision and cannot inherit the original screen's identity.

**Frozen continuation inventory**

Before continuing after a qualifying failure, write an immutable amendment that records:

- The current scientific-registry hash, original 36 run IDs and all original settings.
- Every existing attempt and its completion/failure receipt; the reviewed classification and evidence for each terminal numerical failure.
- The exact remaining unrun IDs in the original manifest order, with fresh attempt IDs, commands and a bounded local execution deadline.
- Valid completed IDs that will be verified and retained, with their original source/run hashes and the original first-valid selection rule.
- The terminal IDs that will not be retried, plus the updated sealer/scorer registration and passing synthetic fixtures.

All 36 run IDs remain in the study inventory and denominator. A terminal entry has an explicit failure status and null/unavailable metrics, never an invented depth, zero error, infinity substituted into an average, or a value copied from another arm. Report completed and terminal counts separately; “36 accounted for” is not “36 successful reconstructions.” Partial predictions from a failed run cannot become a valid completion.

Continue only the enumerated unrun cases, using the unchanged per-case model runner, existing scientific settings and original source identities. Do not edit bound model/launcher source or active registrations. A separate versioned recovery controller, if implemented, must preserve those identities and verify every receipt. No source or artifact may change during another active job.

**Consequences for nomination and comparisons**

- Any terminal numerical failure for P3 or P4 disqualifies that candidate, even if a later or different attempt completes. Preserve any valid predictions for clearly labeled descriptive results; do not erase the failure.
- Any terminal numerical failure in a required P1 state makes that direction's nomination gain unevaluable, including when another attempt completed. A missing valid P1 completion has the same consequence. Nomination then fails because both directions are required; do not substitute P0, another arm, or a reduced scene set as the nomination baseline. Any surviving valid P1 measurements remain descriptive evidence.
- Any other required control without a valid completion makes its corresponding scene/direction/arm comparison unevaluable. Do not silently shrink the paired denominator or present a partial comparison as the full registered contrast.
- The P3/P2 and P4/P5 mechanism contrasts require their matched valid states. A missing detached control prevents that mechanism claim and subsequent advancement for that candidate until the predeclared evidence requirement is met through a new justified study.
- Means over an incomplete registered set remain unavailable. Available per-view/per-scene measurements may be reported descriptively with their coverage, but cannot satisfy the original accuracy, mechanism or rental gates.

An unevaluable or disqualified nomination does not release rental funds. Preserve the bounded local diagnosis/redesign rule from the goal; this recovery specification does not grant additional redesigns, repeats, budget or permission to choose a different primary endpoint.

**Code and release work still required**

The current launcher rejects any failed/partial same-prefix attempt, and a fresh prefix restarts from the first job. The current sealer requires a valid completed attempt for every run ID. Its existing `FloatingPointError` classification does not implement the terminal-status behavior above. The scorer currently expects complete metric inputs. No existing command should be described as supporting this amendment.

If a qualifying failure occurs, implement a separate versioned continuation controller or explicit audited command inventory, a terminal-aware sealer, and a scorer that propagates unavailable comparisons without reducing denominators. Preserve the original scientific registry and successful attempt identities. The new evaluator must hash-link the previous evaluator and this amendment, and continue to select the earliest valid completion by completion time, then attempt ID, while retaining every failure.

Before any held-source labels or accuracy scores are accessed, freeze the amendment and the new evaluator sources/registration, pass fixtures, commit the code/records, and seal the full accounted-for inventory. Required fixtures include terminal candidate disqualification, P1 failure in either direction, a missing detached control, unclassified/infrastructure failure blocking release, mixed identities, changed bytes, partial predictions, an attempted denominator reduction, and first-valid selection with preserved failures.

Do not relax this policy or change evaluator/selection rules after scores are read. If the amendment cannot be implemented and verified without compromising the frozen study, retain the unresolved outcome and diagnose it; do not claim the screen succeeded. Until a qualifying failure actually occurs, continue the existing registered batch and use its existing 36-completion seal.
