## B. Change only the gradient-bearing camera call

In `third_party/TCO/tco_vggt_lora.py` the adaptation loop calls the camera before the depth head. The pinned `base_models/vggt/vggt/heads/camera_head.py` reads the last tap, selects the camera token for every view, normalizes it and executes four iterative refinements. It returns a list of four pose encodings. The previous pose estimate detaches between refinements as part of the original implementation. Preserve that behavior and cross-view attention.

Given the final tap $z$, camera mapping $C$, and derivative $g$ arriving from the original loss, the backbone needs the vector–Jacobian product $J_C(z)^T g$. Checkpointing reruns the same camera calculation during backward so fewer forward tensors must stay live while depth is computed. Parameters, still-needed taps and some autocast allocations can remain live. Previously allocated memory rose from 5.50 to 7.03 GiB across the camera interval. The native first eight-image depth call later failed on a 260 MiB request at 8.69 GiB allocated. The experiment must measure how much of the earlier increase is actually reclaimable.

* **Native control:** ordinary camera and ordinary native DPT. **Candidate:** checkpoint the complete native camera forward on the gradient-bearing adaptation path. Both arms keep the original depth-head implementation, including the default maximum of eight frames per call: five views form one batch of five; ten views form eight plus two. All views continue jointly through the transformer and renderer. Log actual depth call bounds.
* Capture the original bound camera method before wrapping. Pass the final tap explicitly into `torch.utils.checkpoint.checkpoint`. The pure closure returns the tuple of all iteration outputs from the native camera, forwarding the actual iteration count through an immutable binding. Rebuild the list at the caller. Use `use_reentrant=False, preserve_rng_state=True`, preserve input order, dtype and autocast, and bypass checkpointing for initial/final no-grad calls. For any caller outside the qualified adaptation path, delegate to the native method. Keep logging, mutation, scoring and rendering outside the closure. Avoid capturing the full list of live taps in it.
* CPU fixture in the pinned runtime: a small instance of the actual camera head, distinct views, matched weights and full refinement count. Check every iteration output, last-tap gradients with fixed adjoints on the last pose and on all returned poses, and a backward replay on gradient-bearing calls only. Test five and ten views, unchanged no-grad results and original output-list API. Use FP32 `atol=1e-6, rtol=1e-5`, publish max discrepancies and preserve the intended between-refinement detach.
* GPU qualification: zero-update native/candidate at full size, then two reduced-raster fixed-adjoint updates on Heads seed 42 (224 × 294). Check identical initialization, renderer draw order, depth batch shapes, camera/depth predictions and frozen weights; compare each of the 384 LoRA tensors' gradients and updates for each step, including zero gradients. Use the [prior qualification procedure](../scripts/check_tco_full40_recompute.py), including its forward-hash checks, near-zero treatment, maximum per-tensor relative L2 of 1e-4 for factors and 1e-5 for outputs. Repeat the dummy-reference leak test. Treat these as implementation checks and use the original real-loss path for research scores.
