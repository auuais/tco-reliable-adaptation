## 1. Questions and prior evidence

1. When identical, signed derivatives from the **actual** TCO loss enter VGGT, how much variation appears in LoRA gradients and Adam updates? How does that compare with the variation obtained by differentiating the same renderer inputs repeatedly?
2. Can we evaluate all four camera refinements while storing backward activations only for the last one?
3. Can memory freed in the camera head buy enough transformer activation storage to shorten a full reconstruction? Is a measured placement of those activations better than a simple placement at the same peak memory?
4. On new five-view windows, do both mean directed surface errors stay within **1% relative degradation** of ordinary local full-40 TCO on each dataset?

Ordinary TCO and whole-camera checkpointing peaked at 7.822 and 6.302 GiB in the five-view Heads probe. The earlier camera study measured 36.07% lower normalized latency on 7-Scenes and 1.88% higher on ETH3D. Those data support a memory hypothesis and motivate fresh timing controls. In the latest study, repeated native first forwards matched but the worst first-update preclip gradient tensor differed by 1.4909% relative L2. All six same-seed native pairs exceeded 1% on both final geometry errors. Independent rescoring was stable. The exact surrogate-gradient tests enabled deterministic PyTorch and a cuBLAS setting, while the real-loss tests used production settings. Both the incoming derivative and the backend changed. This experiment varies them separately. ## 3. First experiment — replay real derivatives

Let the four outputs at the active loss boundary be `Y = (depth, depth_conf, camera_poses, intrinsics)`. With model parameters θ, the update uses `g = J_Y(θ)ᵀ q` where `q = ∂L_total/∂Y`. Changing q at a fixed model state tests sensitivity to the loss derivative. Repeating the backward with identical q and Y tests the remaining model-backward variability under that backend. Neither comparison requires reference depth.

**Capture.** Start with five-view Heads/seq-01, frames 0,200,400,600,800, seed 42, width 294, two real updates. Use the existing [renderer fixture](../scripts/check_tco_render_lifetime.py) and [matched-state hooks](../scripts/run_tco_render_lifetime.py). Capture the signed **total** loss gradient at each of the four live outputs on ordinary backward using nonmutating hooks, or an independently validated detached-leaf VJP. Save a fresh same-trajectory bundle for the state immediately before **each** update. Include raw boundary values, named q tensors, complete adapter and Adam state, CPU/CUDA RNG before forward, before/after view permutation and before backward, actual source/target indices, autocast/backend settings, shapes, strides, dtypes and loss components. Keep native `None` distinct from a zero derivative. Preserve signs and native bytes, including BF16, and hash dtype/shape/bytes. The inherited general export converts values to FP32. Historical input captures and Adam snapshots belong to separate runs and cannot jointly certify update two.

**Replay.** Restore the same pre-update state, rebuild the live differentiable model outputs, and verify their four named hashes before injecting q. Pass all active outputs and corresponding q tensors together to `torch.autograd.backward` once. Preserve the real renderer's RNG advancement, then run the same clip and **one** Adam step. Injecting again through pose encodings or extrinsics would double count a derivative. Restore the saved state for the second matched-update test. Keep independently evolving two-update trajectories as a separate diagnostic.

| Test per captured update | Inputs and repetitions | Readout |
|---|---|---|
| Native end-to-end | A hooked capture with ordinary backward and two independent ordinary control processes under production settings | Forward hashes, losses, permutations, parameter inventory and native spread. Check agreement of the on-graph q with the detached-leaf calculation. |
| Identical q | Use one common signed q in three fresh native model backwards per backend | Compare preclip and postclip gradients, clip norm, Adam moments/counters and factor deltas. |
| Independently evaluated q | At fixed detached Y, loss settings, RNG and draw, generate three real q bundles. Replay each at the same state. Feed each backend the same three bundles whenever Y matches. | Compare differences in q, resulting g and the optimizer step. Record exact equality if the repeated renderer derivatives match. |
| Sensitivity and controls | Flip the sign of one verified active q and show that preclip gradients change. Retain the earlier detached-opacity renderer control. Also try an absent or misnamed required leaf as a harness failure. | The verifier must detect sign/routing errors and distinguish missing, zero, and nonfinite values. |

Cross the two replay rows with **production** and **deterministic** execution in separate processes. For the latter set `CUBLAS_WORKSPACE_CONFIG=:4096:8` before CUDA initialization and enable deterministic algorithms. Record actual attention backend and unsupported operators. If backend forwards differ, use backend-specific matched native anchors and disclose that cross-backend attribution is limited. For each tensor check presence, shape, dtype and finiteness, then `||a-b||₂ ≤ 1e-6 + r ||b||₂`, with r=1e-5 for predictions or losses and r=1e-4 for gradients, adapter factors and floating optimizer arrays. Counters and view choices must match exactly. Publish absolute norms and differences for near-zero tensors, overall and worst per-tensor relative L2, worst named layer, and gradient cosine for nonzero pairs. Relative differences in a tiny or newly initialized factor alone are weak evidence. If an actual q difference exists, report its amplification into preclip g using both absolute and relative changes.

**Decision.** If fixed production q already gives different backwards, quantify the residual at fixed input. If fixed q is stable and regenerated q changes g, quantify that contribution. Both can occur. A broken boundary, state mismatch or undetected negative control requires repair and a repeat of affected fixtures. Native variability or an unavailable deterministic kernel can leave attribution unresolved. Continue clean engineering measurements in that case. Never describe parity as established by relaxing a threshold. The headline quality test uses independent real 40-step trajectories.
