# Does correcting the focal prior inside TCO improve dense reconstruction?

The offset-25 image experiment tests whether a model can select a valid focal target. This pilot tests whether the selection improves the point map after 40 original TCO updates. We prepare its inputs locally while the replication runs. Execute a paid batch only if the replication selects a method for a dense pilot and the remaining calibration budget covers the quoted session.

## Design

Use the same three development windows with the five frames at offsets 25, 225, 425, 625 and 825. The affected camera is fixed before the replication results, view 0 for Heads, 2 for Chess and 4 for Fire. In each scene test a spurious or genuine focal outlier for each sign of the 1.12 factor. The erroneous and valid member of each pair has exactly the same supplied intrinsics and poses. Apply the already specified mild pose error with seed 137 to all pairs. This gives 12 cases, with an affected reference view in one scene and non-reference views in the other two.

For each case run three separate fresh full-size GPU models with each of two optimizer seeds, 42 and 123. The policies retain the supplied focal, always replace the outlier with the neighbor median, or use the method selected by the frozen replication. Each of the 72 runs observes the original GPU VGGT prediction from its ordinary initial forward pass. Use that exact prediction for the adaptive decision. If the selected method requires the two track folds, use only the image-derived scores for this input hash and supplied pose rig, record the cost of matching, and disclose any cached calculation. Keep pose targets unchanged across all arms. Save initialization, actual target decision, all 40 gradient norm/step records, the unadapted point map, the final point map, compute time and peak memory. Time spent logging or downloading is separate from a claim about model speed.

Use original TCO at LR 0.0003, 518 × 392, five views, normal mixed precision, and unchanged released visual and camera loss weights. No depth, reference points, correct focal target, fault/valid label or scene-specific branch enters the policy. Upload inference inputs only. Score on the local machine after collection. Use the original registered RGB and released nominal camera conventions to lift registered axial depth on the exact cropped raster. Preserve both reference results.

## Analysis and spending

For each execution and reference, divide mean accuracy and completeness distance by their own frozen-initial counterparts, then average the two ratios. Average over the four cases and two seeds within scene, then weight scenes equally. Lower is better. Report raw distances, normal consistency, every scene, both seeds, wrong edits and frozen-no-adaptation results. The actual adaptive runs supply their own predictions; a lookup of a fixed arm cannot stand in for the model execution. Compare the adaptive decisions from the GPU head with the already published CPU FP32 decisions separately.

Use the registered RGB geometry as the primary physical reference. For progression to transfer seek at least 5% improvement against the best of keeping the metadata, always replacing it, and the frozen initial baseline. Require the paired improvement against that comparator to have the same direction at both seeds, no more than 2% aggregate regression in either distance component, and no aggregate harm against unchanged metadata on the released reference. A three-scene pilot cannot establish cross-dataset robustness. Reporting includes all settings and failures regardless of the outcome.

The calibration stage has used an estimated $0.95–$0.99 of $3. Allow at most $1.50 additional for this pilot, including setup, storage while running and shutdown. The existing weekly 5% stop applies throughout. Keep the $25 transfer allocation reserved until a qualifying reconstruction result. Preserve terminal records and two verified local copies.
