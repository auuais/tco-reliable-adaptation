# Can separate LoRA step sizes improve MASt3R depth after alignment?

**Handoff to SOL · 19 November 2026 · Planning only.** On explicit resume, test whether scaling early and late decoder updates separately improves metric depth on unseen rooms. Use the local RTX 3080, one GPU job at a time. RunPod allocation is **USD 0**. A verified negative finding on the development rooms is a complete outcome. The source revision for the preceding experiment is `eb7fde7ae653eae8d8c7409476f871e78fe0c1e7`.

## Why run this experiment

On three rooms, adaptation measurements chose the best of four scalar steps in five of six cases. Mean held-out depth error improved by 2.43% for earlier observations and 0.13% for later observations versus the fixed full step. Even picking the best of the four using the answers would have yielded only 0.14% in the later direction. The upper end of that grid was best in two later cases. A fair next experiment must give a larger scalar step a chance to win. The open question is whether two parts of the same update affect the final depth differently and whether sparse observations can identify which one helps a room. ## Method and equal-cost baseline

Use the previous sensor-only P3 first Adam step exactly once per room and temporal direction. The backbone stays frozen. Keep the same rank 4 adapters, alpha 1, seed 42, learning rate 0.0001, clipping at 1, five views and 20 directed pairs. Write the proposed update as two disjoint parts, ΔE for blocks 0–5 and ΔL for blocks 6–11, in **both** decoder branches (`dec_blocks` and `dec_blocks2`). Apply one pair of multipliers to the whole scene. In effective weight space the candidate is W(a,b) = W₀ + aΔE + bΔL. Along the diagonal a = b this reproduces the scalar method. Off the diagonal we can ask whether favoring one group improves the aligned scene.

| Candidate reconstructions available to a selection rule | Early and late multipliers (a,b) |
|---|---|
| Shared by both rules | (0,0), (0.25,0.25), (0.5,0.5), (1,1), (1.5,1.5) |
| Two additional scalar choices | (0.75,0.75), (1.25,1.25) |
| Two additional split choices | (0.5,1.5), (1.5,0.5) |

Each rule gets seven complete reconstructions and one gradient calculation. Together they require **nine distinct reconstructions per case**. Share identical endpoints by digest across the two rules. From each before/after snapshot, assign each factor using its group's multiplier, starting from the same original state for every candidate. Check that A is unchanged in this first step with initially zero B. Scaling both factors independently from zero would square the intended multiplier. Assert exact original and full snapshots at (0,0) and (1,1) and equivalence with the old scalar assignment at every diagonal value. Verify 144 wrapped projections, 1,032,192 adapter scalars, all indices assigned once, and the original frozen model hash.

Every endpoint gets fresh FP32 inference, matching, and native 300/300 alignment. Use identical prior settings, partitions, and metric scale convention across both rules. For each rule choose the minimum equal-view **selector** mean absolute error (MAE) in mm. For candidates within 0.05 mm of the best, prefer the smallest effective update norm, then the lexicographically smallest (a,b). Since the two groups are disjoint, squared norm equals a²‖ΔE‖² + b²‖ΔL‖². Use the effective LoRA weight changes for these norms. Keep zero as an eligible choice. Record full and per-rule equivalent execution cost and actual cache reuse.

## Stage 1  Measure the opportunity on exposed rooms

1. Use exactly the previous six room and temporal-direction cases in `apt1/living`, `apt2/kitchen`, and `office2/5b`. Reuse verified input and first-step snapshots. On a development case, check the old four diagonal states against their sealed predictions, selector scores, scale and held pixel masks. Reuse archived diagonal outputs only after proving identity of inputs, code path, weights and factors. Record fresh vs reused counts. A disagreement with the bridge needs a diagnosis before interpreting new outcomes.
2. Run the expanded scalar and split candidates and seal predictions and both adaptation-only choices. Using the already-exposed held labels, find the lowest held error within each seven-candidate set for each case. Average these per-case minima equally across rooms, separately for earlier and later. Define gain as 100 × (scalar mean − split mean) / scalar mean. Report the **hindsight comparison** and the **actual selector comparison** separately. A useful retrospective choice can still be hard to identify from sparse data.
3. Test the mechanism on the shared valid selector pixels. Record the signed change in aligned metric depth from (1,1) to each off-diagonal endpoint per view, plus the change to (0.5,0.5) and (1.5,1.5). Report their RMS in mm and cosine similarity to the scalar displacement from (0.5,0.5) to (1.5,1.5). Mark zero-norm comparisons undefined. Repeat (1,1) on a prespecified case, `apt1/living` earlier, and report the repeat difference. If repeat variation can change a gate decision, verify affected endpoints before drawing a conclusion. These diagnostics help explain what native rematching and alignment do to each perturbation.
4. **Open the fresh rooms only if** the split family's hindsight mean beats the scalar family's hindsight mean by at least 1.0% in **each** temporal direction and the real adaptation-selected split lowers the mean versus the real scalar selector in both directions. Evaluate thresholds on unrounded values. This is a conservative decision about spending the holdout. On a miss, publish all six cases, the two comparisons, which choices won, and any numerical uncertainty. End the goal with the holdout preserved. A boundary winner establishes a finding only for this grid.
