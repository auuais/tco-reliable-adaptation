# Can ten native-batched views finish 40 TCO updates on the RTX 3080?

**SOL execution handoff, 25 November 2026. Study `tco_render_lifetime_v1`. Start experimental work when the user resumes the paused goal. All experiments in this study run on the local 10 GiB RTX 3080. Rental budget is USD 0.**

The practical target is ten views at 392 × 518, a full 40 updates under the existing 8.75 GiB process cap, and both five-view surface errors within a 1% relative increase on each of 7-Scenes and ETH3D. The scientific question is whether removing work or storage that the active loss does not use can achieve this while preserving its gradients. The deliverable is a reproducible answer, including a negative or inconclusive one. A passing study earns a proposal for an independent higher-memory test. Paid execution requires a separate decision.

## 1. What failed, and where to start

Use commit `cc3cd1d1d895d6ff7020bd66c897241ba6d814ce` as the evidence baseline. Native TCO failed in its first eight-image DPT depth chunk. Checkpointing the camera head saved 1.52 GiB on all 45 paired five-view runs. At ten views it completed one optimizer update, then two clean attempts and one profiled attempt failed in the **forward RGB rasterizer during update 2**. CUDA requested 24 MiB with 8.66 GiB allocated. In the profile, current allocated memory on entry to the loss rose from about 7,988 to 8,094 MiB across those two updates. The 24 MiB request identifies the failed allocation. The complete backward pass and later updates may require more headroom. [Original screen](../results/tco_courtyard_camera_v1/screen.json) · [Previous quality results](../results/tco_courtyard_camera_v1/README.md)

Start with these hypotheses, in this order.

1. **Unused target normals occupy memory during the RGB render.** In the pinned `third_party/TCO/objective.py`, `depth_multiview_consistency_energy` unprojects target depth, computes two spatial gradients, a cross product and normalized target normals before calling the RGB rasterizer. Under the study config, normal-loss weight is zero and visualization is off. A single contiguous ten-view FP32 XYZ field at this raster would occupy 23.24 MiB. Measure the actual dtypes, storage and lifetimes. **Source** normals still set Gaussian rotations and scales and must be computed.
2. **Old gradients live through the next forward.** In `third_party/TCO/tco_vggt_lora.py`, `TCO_VGGT_LoRA.forward` calls `zero_grad(set_to_none=True)` after producing the next loss. The previous step’s gradient buffers can therefore overlap its render. Adam moments are persistent optimizer state and must survive. Measure each separately.
3. **If both changes together still lack headroom, checkpoint native-sized depth chunks alongside the camera.** Depth activations span the render. Recomputing them during backward could reduce that overlap while preserving the original depth grouping. The previous depth-only eight-frame checkpoint reached a backward OOM. The earlier successful one-image policy completed 9/9 ten-view runs at about 8.29 GiB but changed depth batching and did not establish the joint quality margin. [Previous factorial and capacity results](../results/tco_full40_recompute_v1/README.md)

## 2. Preserve the mathematical experiment

Use the existing local full-40 `four` control. It retains taps 4, 11, 17 and 23, runs all 24 frame/global stage pairs, uses the existing patch-embed placement, and adapts all 384 LoRA tensors. Keep rank 4, alpha 16, dropout 0, Adam LR 0.0003, norm clipping at 1, unchanged AMP scopes and final FP32 unprojection. This is the same local comparator used in the prior study. The shipped YAML lists 0.001 and the registered runner overrides it. Keep the same RGB, supplied poses and intrinsics, pixels, scorer, and frozen base parameters in all arms. Native DPT dispatch is one batch of five or batches of eight and two. Record actual spans in original and recomputed forwards.

For the active multiview term let `d` be expected rendered depth, `z` predicted target depth, `a` ED opacity, `c` rendered RGB and `I` observed target RGB. Over the actual permuted target batch, the implementation uses

```text
v = float(d <= z + 0.0001 * mean(z))
w = a * v
Lrgb = sum(w * mean_channels(abs(c - I))) / (sum(w) + eps)
```

Keep the same threshold, dtype-dependent epsilon, reduction order, active pose and intrinsics terms, and the 0.2 multiview coefficient. Source geometry, the ED pass, visibility, and gradients through the ED alpha and denominator remain essential. The pinned group code draws one CUDA permutation per scene per update. With the configured 100 groups and these view counts, one source renders into **every permuted target, including itself**. Preserve ED and RGB call order and shapes. Skipping an unused target-normal calculation leaves this expression unchanged in exact arithmetic. Clearing a spent gradient changes no Adam input if all consumers have completed and the next backward starts from the same empty gradients. Neither argument guarantees identical 40-step CUDA trajectories.

| Arm | Camera | Target-normal work | Previous LoRA gradients | DPT |
|---|---|---|---|---|
| Native | Ordinary | Original | Original lifetime | Ordinary, native batches |
| Camera | Checkpointed | Original | Original lifetime | Ordinary, native batches |
| N | Checkpointed | Skip only when unused | Original lifetime | Ordinary, native batches |
| G | Checkpointed | Original | Clear before the next forward | Ordinary, native batches |
| NG | Checkpointed | Same guard as N | Same clearing as G | Ordinary, native batches |
| NG+D, conditional | Checkpointed | Same guard as N | Same clearing as G | Checkpoint within the native batches |

For N, enter the native target-normal branch whenever the normal term or active visualization consumes its result. Preserve visual output, no-grad behavior and positive-normal configurations. For G, move clearing to the start of the next iteration, before aggregation, with equivalent first-iteration semantics. Do not clear final gradients earlier than native on return. Assert that clipping, Adam, logging and any registered post-step audits finish before clearing. Preserve parameter, moment and step-counter values. NG+D reuses non-reentrant per-chunk checkpointing with RNG preservation and unchanged camera checkpointing. Keep gsplat itself native in all arms. Diagnostic-only candidates such as releasing ED metadata, cold predictions or unprojection buffers belong in the final diagnosis if relevant. Adding them during this study would confound these ablations.

2. Promote the first qualified two-update passer in the fixed order **N → G → NG** to a clean 40-update Heads pilot.
