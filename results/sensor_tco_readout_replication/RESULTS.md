# Camera calibration with four retained backbone features

The first of the twelve planned RTX 3080 runs reached its 30-minute limit on Heads with the released cameras. It recorded two forward losses and one optimizer gradient snapshot. The worker produced no final 3D prediction. The supervisor exited with code 1 and the other eleven cases never started. This leaves the effect of calibration during adaptation unresolved. [All twelve job records](interruption.json) · [Study protocol](../../manifests/sensor_tco_readout_replication.json)

The input, initial predictions, initial adapters and random-number state matched the original completed Heads control by SHA-256. Both first losses were 0.322060. The second loss was 0.262080 for the original control and 0.269871 with the four retained features. The comparison therefore supports matched initialization. It provides no estimate of numerical equivalence across a full CUDA trajectory. [Original control](../sensor_tco_v17/RESULTS.md)

During the stall, a nonblocking stack sample showed the main thread in backward propagation and a checkpoint recomputation thread waiting at the backbone position lookup. The device reported about 10,014 MiB in use across processes before shutdown and 546 MiB shortly afterward. Those device-wide observations cannot identify the cause of the stall or the run's peak allocation. The full-size engineering test cost **$0 in cloud compute**. A separately registered eight-update probe moves immutable FP32 projection weights to the host after adapter initialization.
